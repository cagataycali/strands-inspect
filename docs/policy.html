Policy reference

Dogwood, the policy language of strands-inspect.

Dogwood is Cedar with a temporal sub-language. A .dw file is a list of permit / forbid rules over (principal, action, resource) with when / unless conditions. Forbid always wins; nothing matched means deny. strands-inspect ships a pure-Python, stdlib-only implementation (strands_inspect.dogwood) and uses it for every @watch policy; @lock projects the same file onto the kernel sandbox.

// the shape of a rule
@id("name-shown-in-the-violation")
permit | forbid ( principal, action == Inspect::Action::"file.read", resource )
when { context.input.path like "/data/*" }
when temporal { formerly within 1h Inspect::Action::"network"::request{} };

The Inspect action schema

principal is the watched function, Inspect::Function::"module.name" with attributes module and name. resource is the process, Inspect::Process::"<pid>" with pid and cwd. action is one of the 20 hooked categories; five action groups (file, net, os, process, meta) let one rule cover a family: action in [Inspect::Action::"net"]. Every action's context.input carries detail (the one-line description) and op (the hooked callable, e.g. open, shutil.copy, subprocess.Popen) plus the typed fields below. context.system is { now: datetime, session: String }; the response event adds context.output.allowed.

The schema ships as strands_inspect/dogwood/inspect.cedarschema and the reference dogwood validate accepts every preset against it.

Presets

A preset name given to @watch(policy=...) loads one of these files from strands_inspect/policies/. A permit annotated @ask is granted only after a y/N prompt.

allow_all

// allow_all: every hooked action is permitted and recorded in the session trace.
// This is the default of @watch: see everything, block nothing.
@id("allow-everything")
permit ( principal, action, resource );

deny_all

// deny_all: nothing is permitted. Dogwood is default-deny, so an empty policy set would
// behave the same; the explicit forbid names the rule in every PolicyViolation.
@id("deny-everything")
forbid ( principal, action, resource );

deny_network

// deny_network: everything is permitted except the network. `net` is the action group
// that holds `network` (connect / urlopen / requests / http.client) and `net.socket`
// (bind / listen / send). Forbid always wins over permit.
@id("allow-everything")
permit ( principal, action, resource );

@id("deny-network")
forbid ( principal, action in [Inspect::Action::"net"], resource );

deny_write

// deny_write: read-only filesystem. Writes, deletes, moves and permission changes are
// forbidden; everything else (reads, network, subprocesses, imports) is permitted.
@id("allow-everything")
permit ( principal, action, resource );

@id("deny-file-mutation")
forbid (
    principal,
    action in [
        Inspect::Action::"file.write",
        Inspect::Action::"file.delete",
        Inspect::Action::"file.move",
        Inspect::Action::"file.chmod"
    ],
    resource
);

sandbox

// sandbox: the function may read files and import modules; every other hooked action is
// denied. Dogwood is default-deny, so only the two permits are needed: no network, no
// subprocess, no writes, no process control, no ctypes/eval.
@id("allow-file-read")
permit ( principal, action == Inspect::Action::"file.read", resource );

@id("allow-import")
permit ( principal, action == Inspect::Action::"import", resource );

strict

// strict: like sandbox, but every file read and every import needs the operator's
// interactive approval. A permit annotated @ask is granted only after a y/N prompt;
// everything else is denied by default.
@ask
@id("ask-file-read")
permit ( principal, action == Inspect::Action::"file.read", resource );

@ask
@id("ask-import")
permit ( principal, action == Inspect::Action::"import", resource );

Temporal conditions

Inside when temporal { ... } a rule can look back at the function's own event trace: one request event per hook check and one response event with output.allowed after it. Every operator carries a mandatory window; windows are closed (an event exactly W back is in). History is keyed per watched function, so another function's calls are invisible.

formtrue at the current check when
formerly within 5m Psome event in the last 5 minutes (this one included) matches P
previous within 1m Pthe event just before this one is at most 1 minute old and matches P
!P since within 1h QQ happened in the last hour and no P happened at any step after it
A && B, !Aconjunction and negation; there is no ||: write two rules instead
exists (n: Long). ((count_within(1m, P)) == n && n > 3)the number of timepoints in the last minute at which P matched is above 3
sum_within(a, 1h, P{ input.size: a })the sum of size over matching events (an aggregate is always compared: (...) == total)
count_distinct_within(h, 1h, P{ input.host: h })how many distinct hosts matched

predicates

Inspect::Action::"file.read"::request{ input.sensitive: true, input.path: context.input.path } names an action, an event kind and field patterns. A pattern is a literal, context.input.x (the current call's value: "the same path"), a variable bound by exists, or the wildcard _. {} matches any event of that kind.

recipes

// no network or process after a credential-shaped read
forbid(principal, action in [Inspect::Action::"net", Inspect::Action::"os"], resource)
when temporal { formerly within 5m Inspect::Action::"file.read"::request{ input.sensitive: true } };

// no write after the network was touched
forbid(principal, action == Inspect::Action::"file.write", resource)
when temporal { formerly within 1h Inspect::Action::"network"::request{} };

// at most 3 subprocesses per minute
forbid(principal, action == Inspect::Action::"subprocess", resource)
when temporal {
    exists (n: Long). (
        (count_within(1m, Inspect::Action::"subprocess"::request{ input.op: "subprocess.Popen" })) == n
        && n > 3
    )
};

// a second read of the same file is fine only if the first one was allowed
permit(principal, action == Inspect::Action::"file.read", resource)
when temporal {
    formerly within 1h Inspect::Action::"file.read"::response{ input.path: context.input.path, output.allowed: true }
};

The full language (macros with def temporal, the acceptance rules, evaluation semantics) is documented at dogwood-policy.github.io. Not supported here: information providers (Ns::Fn(...)), template slots and Rhai; a policy using them is rejected at parse time with a clear error.

@lock projection

The kernel sandbox knows seven capabilities and no history, so a Dogwood policy is projected statically: a capability is allowed only when an unconditional permit covers every action behind it and no forbid touches any of them. file.read permits whose only condition is context.input.path like "/prefix/*" become a read allow-list. @ask permits and temporal rules grant nothing to the kernel.

networknetwork, net.socket
file_readfile.read (bool or a list of globs)
file_writefile.write, file.delete, file.move, file.chmod, file.link, file.mkdir, file.special, file.fd_io
subprocesssubprocess, os.system, os.exec, process.fork, process.mp
ipcprocess.kill
mmap_execmeta.ctypes
sysctlno hooked action: always denied by a projected policy

Command line and API

python -m strands_inspect.dogwood check   policy.dw                 # parse + expand macros; exit 2 when rejected
python -m strands_inspect.dogwood explain policy.dw                 # every rule, the actions it covers, the @lock projection
python -m strands_inspect.dogwood replay  policy.dw trace.log --schema schema.cedarschema
                                          [--event-schema e.dwschema] [--macros m.dw] [--style corpus|cli] [--unpinned]
from strands_inspect import watch, lock, DogwoodPolicy, dogwood

policy = DogwoodPolicy.from_file("policies/team.dw")    # or .parse(text) / .preset("sandbox")
policy.rules                                             # ['allow-everything', 'no-exfil-after-secret']
dogwood.project_to_kernel(policy.policy_set)             # the @lock dict
dogwood.replay(policy_text, trace_text, schema)          # the reference verdict stream

In .strands-inspect.toml a named policy may be Dogwood: [watch.policies.team] with dogwood = "..." or file = "policies/team.dw"; then @watch(policy="team").

Conformance

The implementation is checked against the reference corpus of dogwood@996d756. Vendored in tests/dogwood_corpus/ and run by pytest: 631 / 631 traces byte-identical across 160 temporal_only cases, 154 macro cases, 18 mixed cases and 38 documentation examples. Against the full reference checkout (python scripts/dogwood_corpus.py --all <checkout>): temporal_only 1061 / 1061, macros 254 / 254, mixed 18 / 18, docs examples 38 / 38; the 21 cases that call information providers are skipped. The reference interpreter is right by definition: expected outputs are never edited here.
